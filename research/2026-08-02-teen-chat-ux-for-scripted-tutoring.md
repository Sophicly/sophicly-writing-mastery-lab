# Teen Chat UX for Scripted Tutoring — the Evidence Base
**Date:** 2026-08-02 · **For:** the audit standard for WML code-served walks (chat asks beside a live document) — FIXLIST #112/#156. Every walk (CW steps, planning ladders, CN, future ports) is audited against §RULES at the end.
**Question:** when a SCRIPTED system serves ~100 sequential chat asks to a 13–16-year-old UK student, what does the evidence say about message length, pacing, progress framing, repetition, register, question design, and carried-over work — and which choices are requirements rather than taste?

**Scope note:** this doc governs the *delivery surface* (how a served message looks, paces, and frames). The *help/escalation* layer is already governed by `2026-07-18-scaffolding-escalation-and-socratic-tutoring.md` and PEDAGOGY.md §7; nothing here overrides a PEDAGOGY ruling (verdicts withheld to the end §13; help ∝ instruction received §1; no gamification — real stats are the motivator).

## 1. Working memory + message length — why one-thing-per-message is a REQUIREMENT for this audience

- **Cowan (2001, *Behavioral and Brain Sciences* — "The magical number 4")** — working-memory capacity in young ADULTS is ~4±1 chunks, not Miller's 7. Anything a message asks the reader to hold simultaneously (criteria, sub-questions, constraints, an example to compare against) competes for those slots.
- **Gathercole, Pickering, Ambridge & Wearing (2004, *Developmental Psychology*)** — working-memory capacity develops roughly linearly from age 4 to ~14–15. Half our audience is still BELOW adult capacity; "4±1" is a ceiling, not a budget. **Luna et al. (2004, *Child Development*)** — cognitive control (holding a goal while executing sub-steps) matures through adolescence; the executive juggling an adult does automatically is exactly what a 13-year-old cannot yet spare.
- **Gathercole & Alloway (working-memory-in-the-classroom programme, MRC-CBU)** — the field observation that maps 1:1 onto chat: children given a multi-step instruction ("get your sheet, write your name, do the first ten") LOSE the later steps while executing the earlier ones, and **teachers misread the overload as inattention**. A student who answers only half of a two-part chat ask is not careless — the second half fell out of working memory the moment they started writing the first.
- **Sweller — Cognitive Load Theory (1988; Sweller, van Merriënboer & Paas 1998, *Educ. Psych. Review*)** — the instruction itself consumes capacity (extraneous load) before the task does (intrinsic load). For writing asks the intrinsic load is already high (composing a sentence under criteria); every extra clause in the ask is stolen directly from the composing.
- **Eysenck, Derakshan, Santos & Calvo (2007, *Emotion* — attentional control theory)** — anxiety consumes working memory: worry occupies the same executive resources the task needs. For a low-confidence writer, an intimidating ask doesn't just feel bad — it measurably shrinks the capacity available to answer it. (This is the mechanism that makes §3's progress-framing a cognitive issue, not just a motivational one.)
- **Compound questions** — survey methodology has treated the "double-barrelled" item as a defect for decades (classic treatment: Sudman & Bradburn, *Asking Questions*, 1982): two propositions in one item yields an answer you cannot attribute to either. This is methodological consensus rather than a single study; stated as such.

→ **One question per served ask is a requirement, not a preference, for this audience:** the second question of a compound ask is placed in the exact memory slot that composing the first answer will evict — for a 13-year-old with GCSE-level anxiety, near-guaranteed loss. The live defect ("two-part question in one message that students cannot answer atomically") is this, verbatim.
→ **Budget an ask at ≤4 held items** (Cowan's adult floor, since half the audience is below it): question + up to ~3 criteria bullets. A 5th criterion doesn't get remembered — it gets ignored, silently.
→ **Criteria as scannable bullets, never woven into prose** — prose forces the student to hold the extraction as an extra task (extraneous load); bullets externalise it. The ask ends on the question (ASK-template law 4c.4) precisely so the question is the LAST thing loaded into memory before the student types.
→ **Long teaching = paged chunks, never a long message** (see §2) — a 200-word bubble is a multi-step instruction in Gathercole's sense.

## 2. Pacing + interaction rhythm — the evidence behind one-bubble-per-tap

- **Mayer & Chandler (2001, *J. Educational Psychology* 93 — "When learning is just a click away")** — the foundational experiment for the Continue chip: the SAME lightning lesson, delivered in 16 learner-paced segments (a click advances each) vs continuously, produced better TRANSFER performance for the click-paced group. The interaction was trivial (one click); the benefit came from letting the learner consolidate each chunk before the next arrived.
- **Segmenting principle (Mayer, *Multimedia Learning*; meta-analysis: Rey et al. 2019, *Educ. Psych. Review*)** — breaking a continuous presentation into learner-paced segments reliably improves retention and transfer (small-to-moderate effect across the meta-analysis). The mechanism is load management: a pause boundary lets working memory clear before the next chunk loads.
- **Chi & Wylie (2014, *Educational Psychologist* — the ICAP framework)** — Interactive > Constructive > Active > Passive engagement, with learning outcomes ordered the same way. A Continue tap is at best "Active" — it manages load but does not itself teach. The CONSTRUCTIVE work happens at the ask, when the student writes.
- **Practitioner consensus (conversational UX):** a wall of simultaneous bubbles reads as a broadcast, not a conversation; a paced rhythm sustains the perception of a turn-taking partner. Stated as consensus — no single controlling study.

→ **One bubble per tap is evidence-backed, not a style choice** — Mayer & Chandler is nearly a direct experimental model of `serveCwChunks` (CLAUDE.md 4b): same content, learner-paced segments, better transfer. A code-served run that dumps all chunks in one frame throws this effect away (the exact defect Neil caught: "all of the messages just came at once").
→ **But the tap must stay trivial.** The chip's job is a consolidation boundary, nothing more. Never make Continue carry content or a decision (that's a pick, §6) — and never inflate chunk count so the student is tapping instead of reading: each chunk should be one idea (~1–3 sentences), and a run of more than ~4–5 teaching chunks before an ask is a lecture wearing chat clothing.
→ **ICAP caps the ambition:** taps don't teach; asks do. If a walk's ratio of teaching-chunks to student-production drifts high, the fix is fewer/shorter chunks, not more taps. The last chunk is always the question and never carries a chip (4b) — the rhythm must always resolve INTO production.

## 3. Progress framing + anxiety — what "Step 1 of 105" does to a low-confidence 15-year-old

- **Goal-gradient (Hull 1932, animal learning; humans: Kivetz, Urminsky & Zheng 2006, *J. Marketing Research* — "The goal-gradient hypothesis resurrected")** — effort accelerates as the goal gets CLOSER: café loyalty-card holders bought faster the nearer the card was to full. Corollary: perceived DISTANCE from a goal is demotivating; a goal perceived as far away generates the least effort of the whole pursuit.
- **Nunes & Drèze (2006, *J. Consumer Research* — the endowed progress effect)** — a 10-stamp card pre-stamped twice (i.e. 12 required, 2 "free") beat a plain 10-stamp card on completion (34% vs 19%). Perceived head-start creates commitment. ⚠ **PEDAGOGY constraint:** their endowment was ARTIFICIAL — fake progress is gamification and is ruled out for Sophicly ("real stats are the motivator"). But WML has the honest version available for free: carried-over work from prior lessons IS real endowed progress — showing "3 of 20 already done (carried from Step 4)" is both true and motivationally optimal (see §7).
- **Koo & Fishbach (2012, *J. Consumer Research* — the small-area hypothesis)** — motivation is highest when attention is directed to whichever portion is SMALLER: early in pursuit, frame progress-to-date ("you've done 3"); near the end, frame to-go ("only 2 left"). Framing the LARGE remainder early ("102 to go") is the measurably worst option.
- **Bandura & Schunk (1981, *J. Personality & Social Psychology*)** — children given PROXIMAL subgoals in a maths programme developed higher self-efficacy, more interest, and better performance than children given the distal whole-programme goal or no goals. The classic educational demonstration that near goals build the confidence that far goals erode. (**Amabile & Kramer, *The Progress Principle*, 2011** — same shape in adults: small visible wins are the strongest driver of engagement day-to-day.)
- **Putwain & Daly (2014; Putwain 2007, *Brit. J. Educ. Psychology*)** — ~16% of GCSE students are "highly test anxious" (~100,000 per cohort); test anxiety depresses performance, motivation and well-being. **Putwain & Symes (fear-appeals programme)** — consequence-of-failure framing raises anxiety in precisely the students who doubt their capability; the message lands worst on those most at risk. A magnitude cue ("105 steps") is not a fear appeal, but for a low-confidence student it is appraised the same way: evidence of how far they are from being good enough. Via Eysenck (§1), that appraisal costs working memory on the very next ask.

→ **Never open with the full total.** "Step 1 of 105" before anything else is the anti-pattern every strand above condemns: maximum perceived distance (goal-gradient), zero endowment, large-area framing, distal goal, delivered to an anxiety-prone cohort. The live defect is this, verbatim.
→ **Frame progress at the STAGE level:** "3 of 8 in Openings" — small denominators keep the goal proximal (Bandura & Schunk) and the gradient steep (Kivetz). The stage is the honest unit: it is a real pedagogical boundary, not an invented milestone, so it satisfies the no-gamification ruling.
→ **The big total is honest and belongs in the AMBIENT UI, not the greeting.** Hiding 105 steps entirely would be dishonest (and Sophicly's stance is real stats); the resolution is placement — total lives in the sidebar/progress counter where a student consults it by choice; the chat surface speaks only in stage-relative terms. A number the student must opt in to see informs; the same number pushed as bubble one threatens.
→ **Switch to to-go framing near a boundary** ("2 left in this stage — then Openings is done") — the Koo & Fishbach crossover, applied per stage.
→ **Endow honestly:** when prior work legitimately advances a stage, open the stage AT that count with attribution ("you've already done 3 of these — carried from your Step 4 plan"), never at zero and never inflated.

## 4. Repetition + re-reading — when re-showing content helps and when it reads as broken

- **Roediger & Karpicke (2006, *Psychological Science* — test-enhanced learning)** — RETRIEVING content beats re-reading it for retention, decisively. The memory benefit of "seeing it again" belongs to the student *producing* it, not the system *re-displaying* it.
- **Dunlosky et al. (2013, *Psychological Science in the Public Interest*)** — the definitive utility review: re-reading and highlighting rank LOW-utility across ages and materials. Passive re-exposure is close to worthless as a learning event — so a repeated frame cannot be defended as "reinforcement".
- **Grice (1975, "Logic and Conversation" — the maxim of Quantity)** — a cooperative speaker gives as much information as required and NO MORE. Humans read violations as meaningful: a partner who repeats a 200-word frame verbatim is heard as either not listening or malfunctioning. In a chat UI this is the mechanism behind "the system feels broken" — repetition is not neutral padding; it actively signals defect.
- **Practitioner consensus (conversational-agent UX):** verbatim repetition is among the fastest destroyers of the conversational illusion; users forgive a wrong answer sooner than a copy-pasted one. Stated as consensus.
- **The one legitimate re-show:** the student's OWN prior work, re-presented at the moment it is needed (their logline when writing the blurb; their plan row when drafting the paragraph). This is context-restoration beside a live document, not teaching-by-repetition — and quoting THEIR words verbatim is ownership-respecting (it is theirs to recognise), whereas re-serving OUR teaching verbatim is a Quantity violation.

→ **A frame is served ONCE per session.** Re-entry to the same context gets a ≤2-line summary + a route back to the full text (📖 Guidance chip / scroll anchor), never the full frame again. The live defect — a ~200-word frame repeated four times — fails Grice, Dunlosky, AND the conversational-illusion consensus simultaneously; there is no reading under which it helps.
→ **Summary-vs-verbatim rule:** system teaching → summarise + link; student work → quote verbatim (short) or point at the document row (long). Never paraphrase the student's words back "improved" — that violates ownership (PEDAGOGY §11-adjacent) and reads as correction they didn't ask for.
→ **If re-exposure to taught content is pedagogically wanted, make it RETRIEVAL:** ask the student to state it ("what are the two things a strong opening does?") — a free, evidence-backed learning event (Roediger & Karpicke) — instead of re-serving the text, which is an evidence-backed non-event (Dunlosky). This is also exactly the sanctioned "deliberate retrieval test" carve-out of the paste-wall law (WML CLAUDE.md #3).
→ **Chunk-level dedupe is auditable:** any ≥2-line system passage appearing twice verbatim in one session transcript = defect, greppable.

## 5. Register + voice for teens — politeness, personalisation, and the patronising cliff

- **Wang, Johnson, Mayer, Rizzo, Shaw & Collins (2008, *Int. J. Human-Computer Studies* — "The politeness effect")** — tutorial feedback engineered for politeness (protecting learner "face": suggestions over commands, we-framing, indirect correction) improved learning outcomes vs blunt direct feedback. **McLaren et al. (2011, *IJHCS*)** — the replication nuance: the benefit concentrates in LOW-prior-knowledge / less confident learners — i.e. exactly WML's stated audience ("many low-confidence writers"). Confident students are indifferent to politeness; struggling ones learn more when their face is protected.
- **Personalization principle (Moreno & Mayer 2000; meta-analysis: Ginns, Martin & Marsh 2013, *Educ. Psych. Review*)** — conversational style ("you", "your", first person) beats formal-impersonal style for learning, with the effect strongest for school-age learners and shorter lessons. First-person Sophia is not a branding choice; it is the evidence-backed register.
- **Mayer & DaPra (2012, *J. Experimental Psychology: Applied* — the embodiment/voice work)** — social cues from a pedagogical agent improved transfer ONLY with a human voice; with a machine voice the benefit vanished. The generalisable finding: learners continuously monitor whether the agent is a social partner, and MACHINE TELLS switch off the social-partner processing that carries the benefit. In a text chat, the "machine voice" is machine PHRASING — internal state leaking into the surface ("not written yet. This beat asks:") is the text equivalent of the robot voice, and by this evidence it doesn't just look sloppy, it plausibly forfeits the social-agent learning benefit. (**Reeves & Nass 1996, *The Media Equation*** — the frame behind all of this: people apply interpersonal social rules to media agents automatically.)
- **Yeager, Dahl & Dweck (2018, *Perspectives on Psychological Science* — "Why interventions to influence adolescent behavior often fail…")** — adolescents are acutely sensitive to STATUS and RESPECT; interventions framed in a way that implies the teen is deficient or being managed reliably fail, and the same content framed as respecting their autonomy and competence succeeds. This is the closest the literature comes to measuring "patronising": a tone that signals low expectations or surveillance triggers disengagement in this age band specifically — harder than in adults.
- **Self-determination theory (Deci & Ryan; Vansteenkiste et al. in education)** — autonomy-supportive language ("you could…", offering choice) sustains intrinsic motivation; controlling language ("you must", "you should have") undermines it. Converges with Yeager on the same design rule from a different literature.
- **British school register** — practitioner judgment, not a study: the credible register for a UK GCSE student is that of a good English teacher — warm, precise, British spellings and idiom, no American cheerleading ("Awesome job!!"), no exclamation-mark inflation, praise that NAMES the specific thing done well (which is also assessment-for-learning orthodoxy). Gushing praise for trivial acts is read by teens as low expectations (the Yeager mechanism) — the patronising cliff is mostly made of unearned praise.

→ **Politeness is calibrated to OUR audience, deliberately:** face-protecting phrasing on pushes and corrections ("this is close — one thing would make it stronger" over "this is missing X") is evidence-backed for low-confidence learners specifically. Note this SUPPORTS PEDAGOGY §13 (verdicts withheld; selecting advances): withholding running verdicts is itself face-protection at the structural level.
→ **First-person Sophia, conversational, always** — never "the system", "the platform", "this beat" (already the protocol voice rule; now with its evidence base).
→ **Zero machine tells on the student surface:** no internal vocabulary (beat, slot, node, field), no state dumps ("not written yet"), no colon-into-template constructions ("This beat asks:"). The test: could a teacher SAY this sentence aloud to a 15-year-old without sounding like a robot? Every served string must pass it.
→ **Praise is specific and proportionate; instructions are invitations where possible** ("try one sentence that…" over "you must write…"). Never praise compliance ("great job clicking Continue") — that is the patronising cliff at speed.

## 6. Question design in tutorial dialogue — one thing at a time, recognition before recall

- **VanLehn (2006, *Int. J. AI in Education* — "The behavior of tutoring systems")** — the canonical architecture of every effective ITS: an outer TASK loop and an inner STEP loop, where the system elicits ONE step at a time, evaluates it, remediates it, and only then advances. **VanLehn (2011, *Educational Psychologist*)** — step-based tutors achieve d≈0.76, statistically indistinguishable from human tutors (d≈0.79). The entire evidence base for ITS effectiveness is built on one-step-at-a-time granularity; there is no evidence tradition for compound elicitation, because the systems that work don't do it.
- **Graesser et al. (AutoTutor, EMT dialogue)** — each dialogue move targets ONE expectation; multi-expectation coverage is achieved by SEQUENCING moves, never by stacking expectations into one prompt. (The escalation ladder within a single expectation is the 2026-07-18 doc's territory.)
- **Recognition vs recall** — one of the most robust asymmetries in memory research: recognition (pick it out) is reliably easier than recall (produce it), because recognition provides the retrieval cue the student would otherwise have to generate. HCI has the same rule independently (Nielsen's heuristic "recognition rather than recall"). Sequencing consequence for tutoring: a recognition ask (pick which opening type this is) can succeed and build confidence where the recall/generation twin (write an opening) would fail — and having just SELECTED the target concept measurably primes producing it.
- **Faded scaffolding (Renkl & Atkinson 2003)** — the validated sequence novice→competent runs worked example → completion → generation: i.e. show → part-produce → produce. Confirm-then-generate is this sequence expressed in chat: confirm understanding cheaply (a pick), then generate (a sentence).
- **Compound-prompt error** — direct error-rate studies in ITS chat are thin; the convergent evidence is §1's working-memory case + survey methodology's double-barrelled-item consensus + the universal ITS practice of single-step elicitation. Stated plainly: this is a strongly convergent practitioner consensus, not a single controlling experiment.

→ **One production per ask — the atomic-ask law.** An ask requests exactly one thing: one sentence, one pick, one confirmation. Multi-part intent decomposes into sequenced asks (VanLehn's step loop) or ONE multi-select pick with a Continue (the CW4 unmet-needs pattern, 4c.8) — never two blanks in one message. Greppable proxy: **one question mark per served ask** (rhetorical questions inside teaching chunks are the exception, and are better rewritten as statements anyway).
→ **Recognition before recall, by default:** when a walk introduces a concept and then requires production, insert the cheap confirm first (pick/label/spot-it) before the generate ask. This is also PEDAGOGY §13-compatible: selecting an answer advances.
→ **The push stays on the current component** (4c.6 twin): a push after a weak answer re-asks the SAME single thing, never bundles "and also fix…" additions — bundling a push is how a compound ask sneaks back in through the correction channel.

## 7. Skipped / auto-completed steps — carried answers without disorientation or redundancy

Direct experimental literature on "how a tutoring chat should present steps done on the student's behalf" does not exist; this section derives from adjacent evidence and is flagged as such.

- **Grounding (Clark & Brennan 1991, "Grounding in communication")** — conversation runs on accumulated COMMON GROUND, and each contribution must be grounded before the dialogue moves on. A system that silently consumes a step breaks grounding: the student's model of "where we are" and the system's diverge, and every subsequent message is interpreted against the wrong state. A numbering jump (Step 4 → Step 9 with no comment) is a grounding failure the student experiences as disorientation or as "it's broken".
- **Visibility of system status + consistency (Nielsen's heuristics; practitioner consensus)** — the system must keep the user informed about what has happened, in the user's own vocabulary; sequences must behave consistently. Auto-completed work is a status change and must be SAID.
- **Grice's Quantity, again, caps the other side:** having announced the carry, re-asking the question anyway (or re-explaining the full step) violates the as-much-as-required bound — redundancy after an announced carry is §4's repetition defect in a new costume.
- **Endowed progress (Nunes & Drèze, §3)** — properly attributed carried work is the HONEST endowment: it raises completion motivation precisely because the student sees credited progress that is really theirs.
- **Ownership (house law, PEDAGOGY-wide):** a carried answer is the student's own prior work relocated — so presenting it verbatim WITH ITS PROVENANCE both grounds the conversation and reinforces ownership ("this is yours, from Step 4"). Presenting it unattributed invites the reading "the machine wrote this for me", which undermines the ownership the whole product is built on.

→ **The carry template (all three parts, ≤2 lines + the quote/pointer):** (1) name the step in student vocabulary, (2) attribute the content ("carried from your Step 4 plan"), (3) show it — verbatim if short, a pointer to the document row if long — then move on. Never re-ask it; never silently skip it.
→ **Numbering never jumps on the student surface.** Either the carried step is shown-as-done in sequence (preferred — it is also the honest endowed progress of §3), or the visible numbering is stage-relative so the jump cannot surface. An unexplained gap in a sequence the student can see = defect.
→ **Offer edit, don't demand review:** a carried answer ends with the option ("happy with it? [Keep] [Edit]") ONLY where editing is genuinely open at this lesson (section-freeze law, PEDAGOGY §6, still governs); where the section is frozen, the carry is stated as fact with no dangling choice.

## THE RULES, COMPRESSED — the audit standard (grep a transcript against these)

1. **One question mark per served ask.** One ask = one production (one sentence, one pick, one confirm). Two blanks in one message = defect; multi-part intent is sequenced asks or one multi-select pick.
2. **An ask ends on the question.** Nothing follows the question line — no afterthought criteria, no "also".
3. **≤4 held items per ask** — question + max ~3 criteria bullets. Criteria are bullets, never prose. A 5th criterion is a defect (it will be ignored, not remembered).
4. **A teaching chunk is one idea, ~1–3 sentences.** Anything a code-served run emits beyond one bubble pages behind a Continue chip; the final chunk is the question and never carries a chip.
5. **Continue chips advance only** — never carry content, a decision, or a disguised pick. And no praise for tapping one.
6. **A run of >5 teaching chunks before an ask = defect** — shorten the teaching, don't add taps.
7. **No full-course total in the chat surface.** The greeting/orientation never states the whole-walk step count; progress in chat is stage-relative ("3 of 8 in Openings"). The honest big total lives in the ambient counter/sidebar only.
8. **Early in a stage frame done-to-date; near the end frame to-go** ("2 left in this stage").
9. **Progress counts real work only.** No inflated or invented milestones; carried real work IS counted, at its true value, with attribution.
10. **A frame is served once per session.** Re-entry = ≤2-line summary + a route to the full text (chip/anchor). Any ≥2-line system passage appearing twice verbatim in one session = defect.
11. **System teaching is summarised on re-show; student work is quoted verbatim** (or pointed at in the document). Never paraphrase the student's words back "improved".
12. **Wanted re-exposure is retrieval, not re-display:** ask the student to state it; don't re-serve it.
13. **Zero machine tells.** No internal vocabulary (beat, slot, node, field, "not written yet"), no state dumps, no template-colon constructions. Test: a teacher could say the sentence aloud to a 15-year-old.
14. **First-person Sophia, British English, conversational.** Never "the system"/"the platform". Praise names the specific thing done; no exclamation-mark cheerleading; corrections are face-protecting ("close — one thing would make it stronger").
15. **Recognition before recall:** where a concept is introduced then produced, a cheap confirm/pick precedes the generation ask.
16. **A push re-asks the same single thing** — never bundles additional demands into the correction.
17. **Carried work: named, attributed, shown, never re-asked, never silently skipped.** Template ≤2 lines: step name + "carried from your [source]" + the content (verbatim if short, document pointer if long). Visible numbering never jumps unexplained.
18. **Help ladder order is fixed and cheapest-first:** more examples → guidance → technique cards → ask Sophia LAST (house law 4c.9; restated here so a transcript audit checks chip order too).
